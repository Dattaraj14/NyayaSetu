# NyayaSetu

NyayaSetu is a web application for understanding Indian legal documents. Upload a PDF, let the backend extract and organize its contents, then ask questions about that document in English, Hindi, or Marathi.

NyayaSetu provides informational assistance. It is not a substitute for advice from a qualified lawyer.

## What it currently supports

- Upload PDF documents up to 50 MB.
- Extract text from text-based PDFs with PyMuPDF.
- Run OCR on scanned and hybrid PDFs with Tesseract.
- Detect legal sections and numbered paragraphs, then divide text into retrieval-friendly chunks.
- Build a semantic search index for each processed document with BGE-M3 and FAISS.
- Ask questions grounded in the uploaded document, with answers generated by Gemini.
- Request answers in English, Hindi, or Marathi.

General legal information mode, summaries, simplification, and translation are not currently exposed as working API features.

## Requirements

- Python 3.10 or newer.
- Node.js and npm.
- PostgreSQL, using the connection settings in `.env`.
- Tesseract OCR with English, Hindi, and Marathi language data for scanned PDFs.
- A Gemini API key for question answering.
- Enough disk space and memory for the BGE-M3 embedding model. The model can be downloaded when the backend first starts.

The backend configuration also allows selecting a CUDA device for embeddings. If CUDA is unavailable, the embedding code falls back to CPU.

## Setup

### 1. Configure the backend

From the project root, create and activate a virtual environment, install the backend dependencies, and copy the configuration template:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
Copy-Item .env.example .env
```

Edit `.env` and set `GEMINI_API_KEY` and the PostgreSQL connection string. The example uses a local PostgreSQL database named `nyayasetu`.

Install Tesseract separately and set `TESSERACT_CMD` in `.env` to the installed executable path if it differs from the example. Confirm that the `eng`, `hin`, and `mar` language data are installed.

### 2. Start the backend

Run this from the project root:

```powershell
uvicorn app.main:app --app-dir backend --reload
```

The API is available at `http://localhost:8000`. Interactive API documentation is at `http://localhost:8000/docs`.

At startup, the backend creates database tables and attempts to preload BGE-M3. The first model load may take time.

### 3. Start the frontend

In a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite, usually `http://localhost:5173`.

The frontend currently points to `http://127.0.0.1:8000/api` in `src/App.tsx`.

## Main API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/` | Backend name, version, and status |
| `GET` | `/api` | Database and service status |
| `POST` | `/api/documents/upload` | Upload a PDF and start processing |
| `GET` | `/api/documents/` | List uploaded documents |
| `GET` | `/api/documents/{document_id}` | Read document details and processing status |
| `POST` | `/api/documents/{document_id}/index` | Build the document's semantic search index |
| `POST` | `/api/chat/{document_id}` | Ask a question about an indexed document |

## Processing and storage

Document records, pages, sections, and chunks are stored through SQLAlchemy. Uploaded files, temporary files, and vector indexes are stored on disk according to the configured paths. Each document has its own FAISS index, so retrieval is scoped to that document.

The frontend waits for document processing to finish, then requests indexing before enabling chat.

## Configuration notes

- `.env.example` uses PostgreSQL. The Python settings contain a SQLite default, but SQLite requires `aiosqlite`, which is not currently listed in `backend/requirements.txt`.
- The settings contain options for multiple LLM providers, but the active chat implementation is Gemini-based.
- OCR settings mention PaddleOCR, while the current OCR implementation uses Tesseract.
- The frontend currently reads some status and source fields using names that differ from the backend response. See the backend and frontend READMEs for details.
